🚀 并行计算复习资料

交互式学习 · 点击掩码查看答案 · 深度理解核心概念

✨ 创作者：Bill Miao

一、核心概念

1. 并行计算：同时利用多种计算资源（多处理器、多核等）解决计算问题。核心是将大任务分解为多个可独立执行的子任务，由多个处理单元并行步骤进行。总结思想：串行计算是计算机顺序执行指令或数据元素，并线性推进特征。

2. 阿姆达尔定律：核心限制是程序中不可并行的串行部分，公式为：

S = 1/[(1-f) + f/p]

其中 f 为程序串行比例，p 为处理器数量，揭示了无论如何增加处理器数量，加速比都会在上限 1/(1-f)，优化关键是减少串行部分占比。

3. Flynn 分类法：四大核心类型，重点掌握 SIMD（单指令多数据流，如 GPU详解 →、向量处理器）和 MIMD（多指令多数据流，如多核处理器、集群系统），明确各类指令流与数据流的匹配特征。

4. 并行效率：衡量资源利用率的核心指标，取值范围 0 < E ≤ 1，公式为：

E = 加速比 / 处理器数量

E=1 为理想状态，实际受通信信息延迟、负载不均衡等影响。

5. C 语言基础：单精度采用数组的类型关键字为 float，双精度为 double。

二、并行编程模型

1. 共享内存模型：多线程/处理器共享同一内存空间，通过读写共享变量实现隐式通信，编程直观简洁，但扩展性受限。线程通常作为处理器调度的基本单位。典型技术为 OpenMP（编译指令驱动 →）、Pthreads（线程库驱动 →），适用于中小型并行任务。

2. 消息传递模型：处理器/节点无共享内存，需通过显式消息发送（send）、接收（recv）完成通信，进程地址空间独立，无数据竞争风险，可扩展性强，典型技术为 MPI，适用于大规模集群并行场景（如气象模拟、基因测序）。

3. 数据并行编程模型：将相同操作并行应用到不同数据上（如 CUDA、SIMD 指令），核心是"单指令多数据"，适配数据密集型计算。

4. 核心区别：通信方式（隐式 vs 显式共享变量）、编程复杂度（低 vs 高）、可扩展性（弱 vs 强），适用规模（中小规模 vs 超大规模）。

三、OpenMP 核心

1. 并行区域构造：编译指令全以 #pragma omp 开头，核心指令包括：

  • #pragma omp parallel（创建并行区域）
  • #pragma omp for（并行循环体）
  • #pragma omp parallel for（创建并行区域并并行化循环体）
  • #pragma omp atomic（原子操作）
  • #pragma omp master（主线程执行代码块）

2. 临界区保护与线程同步：通过 critical 指令或原子操作保护共享资源，避免数据竞争，适配线程并发场景。

2. 关键子句：

  • shared：指定变量为所有线程共享，是线程间数据交互的主要方式
  • private：为每个线程创建变量私有副本，避免线程间干扰
  • reduction：用于规约计算，自动创建私有副本并汇总结果
  • schedule：指定循环分块方式（如 static、dynamic）
  • nowait：忽略工作构造末尾的隐含屏障

3. 同步指令：与 #pragma omp critical（定义临界区，避免数据竞争）、#pragma omp barrier（栅栏同步 →，等待所有线程到达）

4. 核心构造：以 #pragma omp 为指令令牌级，核心构造如 #pragma omp single（仅一个线程执行代码块）。

5. 核心函数：omp_set_num_threads()（设置线程数）、omp_get_thread_num()（获取当前线程 ID）、omp_get_num_threads()（获取总线程数）。

四、Pthreads 核心

1. 核心函数：

  • pthread_create()：创建线程，参数包括线程 ID、属性、执行函数、传递参数
  • pthread_join()：主线程等待子线程结束并回收资源
  • pthread_exit()：线程主动退出并返回状态
  • pthread_self()：获取当前线程的 ID，用于标识线程身份
  • pthread_detach()：将线程设为分离状态，线程结束后自动回收资源，无需 pthread_join()

2. 同步机制：互斥锁（pthread_mutex_t），使用流程为初始化（pthread_mutex_init()）→ 上锁（pthread_mutex_lock()）→ 访问临界区 → 解锁（pthread_mutex_unlock()）→ 销毁（pthread_mutex_destroy()）。

五、CUDA 基础

1. 异构系统：CPU 为主机端（Host，运行操作系统、调用核函数），GPU 为设备端（Device，执行并行计算任务），GPU 常作为协处理器加速集型计算。

2. 核函数：

  • 修饰符：__global__（主机调用，设备执行，返回 void）、__device__（仅设备端程序调用执行）
  • 调用格式：需通过尖括号号定义网格/线程块配置，并通过 cudaDeviceSynchronize() 等待执行完成，参数传递需注意主机端与设备端内存地址规则
  • 核函数名：<<<网格数, 线程块数>>>(参数)，如 Add<<<1, 1024>>>(a, b, c)

3. 线程组织：网格（Grid）→ 线程块（Block）→ 线程（Thread）三级结构，通过 blockIdx、threadIdx、blockDim 获取索引。

4. 内存体系结构：__shared__（共享内存，线程块内共享），优化 CUDA 程序时应尽量利用共享内存减少全局内存访问延迟。

5. 编译相关：编译器为 nvcc，源代码文件后缀为 .cu。

6. 线束（warp）：CUDA 调度单位，典型含有 32 个线程。

7. 性能优化：查看详细优化策略 →

  • ①资源利用最大化，提高并行度，利用流和异步调用实现主机端与设备端并行
  • ②内存吞吐最大化，减少主机-设备数据搬移，打包小块传输为大块，利用共享内存 cache 降低全局内存访问延迟
  • ③指令吞吐最大化，优先使用低位运算符，减少控制流和分支不必要的同步
  • ④内存碎最小化，减少 cudaMalloc()/cudaFree() 调用，避免反复使用设备内存
六、同步与数据安全

1. 数据竞争：数据竞争是指多个线程同时读写同一共享变量，且至少一个步骤制约的逻辑复杂。临界区是访问共享资源的代码段，需保证一次仅一个线程执行。数据竞争会导致程序结果不确定，错误具有随机性、调试难度极大，严重影响耐用性和稳定性。

2. 临界区：临界区是多线程并发执行时，多个线程需访问的共享资源或代码段。若无同步机制，多个线程同时进入会导致数据竞争，访问共享资源的代码段，需通过同步机制保证一次仅一个线程执行。

3. 同步机制：

  • ①互斥锁，强制临界区仅一个线程执行
  • ②栅栏（barrier），使所有线程同步点等待，直至全部到达后继续
  • ③条件变量，实现基于特定条件的等待与唤醒
  • ④原子操作，适用于简单量操作"读-改-写"操作，效率高于临界区
七、工程实践核心要求

OpenMP 编程

1. 并行循环与变量规约的计算：运用 reduction 子句实现聚合计算，掌握并行区域与循环结合用法，编译需开启 OpenMP 支持。

Pthreads 编程

1. 线程创建与参数化选：掌握线程初始化，自定义参数传递方法，实现主线程与子线程协同执行。

2. 互斥锁与线程安全操作：运用互斥锁完整流程（初始化 → 上锁 → 解锁 → 销毁），保障共享变量的安全访问。

CUDA 编程

1. 核函数数据调用用：掌握 __global__ 修饰符使用，核函数调用格式（<<<网格,线程块配置>>>），实现主机端与设备端数据交互。

2. 共享内存优化：运用 __shared__ 修饰符定义共享内存，优化全局内存访问延迟，还配数据密集型算场景。

🎯 SIMD 与 GPU 详解

SIMD（单指令多数据流）

核心概念：一条指令同时处理多个数据元素，适合数据并行场景。

典型应用：

  • 向量处理器：对向量进行批量运算
  • 图像处理：同时处理多个像素
  • 科学计算：矩阵运算、信号处理

GPU（图形处理器）

架构特点：

  • 包含数千个简单核心，适合大规模并行
  • 采用 SIMT（单指令多线程）架构
  • 高带宽内存，适合数据密集型任务

与 CPU 对比：

  • CPU：少量复杂核心，适合串行和复杂逻辑
  • GPU：大量简单核心，适合并行计算

应用场景：

  • 深度学习训练与推理
  • 科学计算模拟
  • 图形渲染
  • 加密货币挖矿

🔧 OpenMP 编译指令驱动详解

什么是编译指令驱动？

OpenMP 通过在代码中插入 #pragma 编译指令，编译器识别这些指令后自动生成并行代码，无需手动管理线程。

优势

  • 简单易用：只需添加指令，无需重写代码结构
  • 渐进式并行化：可以逐步为串行代码添加并行支持
  • 可移植性：不支持 OpenMP 的编译器会忽略指令，代码仍可串行运行
  • 自动负载均衡：编译器自动分配任务到线程

示例代码

#pragma omp parallel for // 并行化循环
for (int i = 0; i < n; i++) {
    result[i] = compute(data[i]);
}

编译方法

需要在编译时启用 OpenMP 支持：

gcc -fopenmp program.c -o program
# 或
clang -fopenmp program.c -o program

🧵 Pthreads 线程库驱动详解

什么是线程库驱动？

Pthreads（POSIX Threads）是一套标准的线程 API，程序员需要显式调用库函数来创建、管理和同步线程。

特点

  • 细粒度控制：完全控制线程的创建、执行和销毁
  • 跨平台：遵循 POSIX 标准，支持 Linux、Unix、macOS
  • 灵活性高：可以实现复杂的线程交互模式
  • 学习曲线陡：需要理解线程生命周期和同步机制

核心函数流程

// 1. 创建线程
pthread_t thread;
pthread_create(&thread, NULL, thread_function, arg);

// 2. 等待线程结束
pthread_join(thread, NULL);

// 3. 互斥锁使用
pthread_mutex_t mutex;
pthread_mutex_init(&mutex, NULL);
pthread_mutex_lock(&mutex);
// 临界区代码
pthread_mutex_unlock(&mutex);
pthread_mutex_destroy(&mutex);

与 OpenMP 对比

特性 OpenMP Pthreads
编程难度 简单 复杂
控制粒度 粗粒度 细粒度
适用场景 数据并行、循环并行 复杂线程交互

🚧 栅栏（Barrier）同步详解

什么是栅栏同步？

栅栏是一种同步机制，确保所有线程都到达某个执行点后，才能继续执行后续代码。

工作原理

  1. 线程到达栅栏点后进入等待状态
  2. 当所有线程都到达栅栏时，栅栏打开
  3. 所有线程同时继续执行

应用场景

  • 阶段性计算：确保上一阶段完成后再开始下一阶段
  • 数据依赖：某些线程需要等待其他线程的计算结果
  • 迭代算法：每次迭代需要所有线程完成当前步骤

OpenMP 中的使用

#pragma omp parallel
{
    // 第一阶段工作
    phase1_work();
    
    #pragma omp barrier  // 等待所有线程完成第一阶段
    
    // 第二阶段工作
    phase2_work();
}

注意事项

  • 所有线程必须都能到达栅栏，否则会造成死锁
  • 过多的栅栏会降低并行效率
  • 某些 OpenMP 指令（如 for）隐含栅栏，可用 nowait 取消

⚡ CUDA 性能优化详解

1. 资源利用最大化

目标：充分利用 GPU 的并行计算能力

  • 提高占用率：增加线程块数量和每个块的线程数
  • 流和异步操作：使用 CUDA 流实现计算与数据传输的重叠
  • 多 GPU：利用多个 GPU 并行处理不同任务
// 使用流实现异步操作
cudaStream_t stream;
cudaStreamCreate(&stream);
kernel<<>>(data);
cudaMemcpyAsync(dst, src, size, cudaMemcpyDeviceToHost, stream);

2. 内存吞吐最大化

目标：减少内存访问延迟，提高带宽利用率

  • 减少主机-设备传输：尽量在设备端完成计算
  • 合并内存访问：确保线程访问连续内存地址
  • 使用共享内存：将频繁访问的数据放入共享内存
  • 避免 bank 冲突：优化共享内存访问模式
// 使用共享内存优化
__global__ void kernel() {
    __shared__ float shared_data[256];
    // 从全局内存加载到共享内存
    shared_data[threadIdx.x] = global_data[threadIdx.x];
    __syncthreads();
    // 使用共享内存进行计算
}

3. 指令吞吐最大化

目标：提高指令执行效率

  • 使用内建函数：如 __sinf() 代替 sin()
  • 减少分支：避免线程束内的分支发散
  • 循环展开：减少循环控制开销
  • 避免不必要的同步：减少 __syncthreads() 调用

4. 内存碎片最小化

目标：高效管理设备内存

  • 内存池：预分配大块内存，避免频繁分配/释放
  • 重用内存：多次计算使用同一块内存
  • 统一内存：使用 cudaMallocManaged() 简化内存管理

性能分析工具

  • nvprof：NVIDIA 命令行性能分析器
  • Nsight Systems：系统级性能分析
  • Nsight Compute：内核级性能分析

💡 优化建议：先确保程序正确性，再进行性能优化。使用性能分析工具找出瓶颈，针对性优化。
